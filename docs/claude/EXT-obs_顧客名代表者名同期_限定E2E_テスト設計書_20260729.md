## 1. テスト前提

1. 本試験は、新規FileMakerスクリプトから既存transportを経由した**実際の呼出し連鎖**
   （FileMaker → `EXT-obs_内部CallPS-PAYLOAD` → PowerShell → Obsidianノート）を初めて通す試験である。
   PowerShell単体の業務ロジック（24ケース）はWindows実機検証で既に24/24 PASS済みのため、
   本E2Eの主目的はロジックの再検証ではなく、**新規FileMakerスクリプトとtransportの結線・実機統合**を
   限定的に確認することである。
2. 使用するFileMaker環境が本番データベースそのものか、テスト専用の複製かを、試験開始前に
   ユーザーが明示すること。本設計書はいずれの場合にも対応できるよう、テストデータ・テストVaultを
   本番と完全に分離する設計とする（詳細は第2章・第3章）。
3. 前提未確認・未充足の場合は試験を開始しない（第10章のチェックリストで判定する）。
4. 試験に使用するFileMaker端末の `z_sysClientPC::OB_VAULTPATH` / `OB_VAULTNAME` は、
   端末単位の設定であり、通常運用（本番Vaultとの同期）にも使われる可能性がある共有設定である。
   本試験ではこれを一時的にテストVaultへ変更するため、**試験前の値を必ず記録し、試験後に必ず
   元の値へ復元する**（第4章・第8章）。これを怠ると、本試験終了後の通常運用が誤って
   テストVaultを参照し続ける事故につながる。
5. `顧客::pk_CLIENT` は AutoEnter `Get(UUID)` のため、値を任意に指定することはできない。
   テスト用顧客レコードを新規作成した時点で自動生成された値を、そのままテストノートの
   `UUID`キーへ転記する運用とする。

## 3. テストVault構成

本番Vault（`【Vault】INS`）とは完全に独立した、試験専用の一時フォルダを新設する。

```text
<TESTKIT_ROOT>\E2E_TestVault_20260729\
└─ 01_顧客\
   └─ 【E2Eテスト】株式会社E2E検証クライアント\
      ├─ 契約一覧.md   （UUID一致・メイン検証対象）
      ├─ 契約.md       （UUID一致・複数ノート一括更新の確認用）
      └─ 補助メモ.md   （frontmatterなし・UUIDなし補助ノート。不変・フォルダ移動の確認用）
```

各ファイルの内容案は次の通り（既存Windows実機検証で使用したTestVaultの形式に準拠）。

**契約一覧.md**
```yaml
---
tags:
  - "【E2Eテスト】株式会社E2E検証クライアント"
  - "検証太郎"
UUID: <顧客::pk_CLIENTの自動生成値をここに転記>
ランク: A
---
E2E限定試験用の本文サンプルです。
```

**契約.md**（同一UUID・複数ノート一括更新の確認用。内容は契約一覧.mdと同形式で可）

**補助メモ.md**（frontmatterなし。UUIDなし補助ノートとして、内容不変・フォルダ移動のみを確認する）
```text
これはUUIDを持たない補助ノートです。内容は変更されないことを確認する対象です。
```

第2.2節のNGコード確認用フォルダは、上記`01_顧客`の直下に、変更後名と同名の空フォルダとして
別途用意する。

`顧客::pk_CLIENT`の自動生成値が確定した時点で、`契約一覧.md`・`契約.md`の`UUID`キーへ
実際の値を転記すること（推測値を先に書き込んではならない）。

## 7. 異常時停止条件

次のいずれかが発生した場合、それ以上のケースを実行せず、直ちに試験を中止し第8章の
ロールバック手順へ進み、状況をChatGPTへ報告する。

- ダイアログに仕様外のstatus／codeが表示された場合（`INVALID_RESPONSE`相当の未知応答扱いを含む）。
- 応答JSONの型検証・必須キー検証でエラーが表示された場合。
- `requestId`不一致の警告が表示された場合。
- テストVault以外の場所（特に本番Vault配下）のファイルが変更された形跡がある場合。
- `z_sysClientPC::OB_VAULTPATH` / `OB_VAULTNAME` が試験中に意図せず本番Vaultを指したままだったことが判明した場合。
- 既存2スクリプトまたはPowerShell本体のSHA256が、試験前後で変化していた場合。
- Gitの差分（`git status --short`）が試験前後で既知状態から増えていた場合。
- 想定していないダイアログ（`カスタムダイアログを表示`以外の予期しないFileMakerエラー等）が表示された場合。
